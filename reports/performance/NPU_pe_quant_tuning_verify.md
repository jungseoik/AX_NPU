# [검증] PE 양자화×튜닝 매트릭스 24종 — NPU 실측 (cos·채널 지연)

> ## ⚠ 2026-09-03 정정 — 이 문서의 1번 결론은 **qbcompiler 1.1.2 한정**이다
>
> 아래 "OPTQ·SWS는 쓰지 말 것" 은 **컴파일러 1.1.2 의 버그였다.** qbcompiler **1.2.0** 으로
> 같은 조건을 다시 돌리면 튜닝 효과의 **부호가 뒤집혀 정확도가 올라간다**(W4A16 0.8795 → **0.9642**,
> W8A16 0.9747 → **0.9951**). 튜닝을 끈 베이스라인은 두 버전이 동일(0.9110 → 0.9126)하므로
> 차이는 전적으로 튜닝 구현에서 나온다. 벤더 회신 수치도 1.2.0 에서 재현된다.
> → **[`NPU_pe_quant_tuning_compiler_version.md`](NPU_pe_quant_tuning_compiler_version.md)**
>
> 이 문서의 24종 수치 자체는 1.1.2 실측으로서 유효하다. 다만 **배포 판단 근거로는 쓰지 말 것.**

**GPU 서버에서 컴파일만 하고 넘긴 24종**([`NPU_pe_quant_tuning_compile.md`](NPU_pe_quant_tuning_compile.md))을
NPU 보유 서버에서 정확도·지연으로 채점한 결과.

## 결론 요약

1. **(1.1.2 한정) 모든 양자화에서 "튜닝 없음(none)"이 최선이었다.** OPTQ·SearchWeightScale은
   9개 조합(3 양자화 × 3 튜닝) **전부에서 cos를 떨어뜨렸다.** W8A16조차 OPTQ를 켜면 0.9937 → 0.9744.
   → **원인 규명 완료(2026-09-03): qbcompiler 1.1.2 의 튜닝 구현 문제.** 1.2.0 에서는 반대로
     정확도가 올라가고 벤더 회신 수치가 재현된다. 상세는 위 배너의 링크 참조.
2. **W4A8_L5A16은 붕괴가 아니었다.** 앞선 실측의 cos 0.2609는 A16 텐서 **이름 지정 방식** 문제였다.
   같은 "outlier 상위 5개"를 `--dump-names` 로 얻은 정확한 mblt 이름으로 지정하면 **cos 0.8790**이 나온다.
   (앞선 실행은 부분문자열 매칭으로 주입 → 의도와 다른 텐서가 걸렸을 가능성)
3. **속도 순위**: W4A8_L5A16 > W4A16 > W8A16. 12채널 기준 572 / 656 / 864 ms(single).
   코어모드 특성(global4=다채널 유리, single=배치 클 때 유리)은 양자화·튜닝과 무관하게 유지된다.

측정: 2026-09-02 / NPU 1장(`/dev/aries7`) / cos = 원본 PyTorch 임베딩 대비(COCO 20장 평균) /
지연 = 채널 N개 배치 완료까지, 3회 중앙값(동기 infer + 스레드풀) / 스크립트 `reports/scripts/verify_quant_tuning_matrix.py`
