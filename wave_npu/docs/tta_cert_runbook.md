| 시험항목 | T1 쓰러짐 / T2 화재 / T3 연기 / T4 침입 / T5 배회 / T6 폭력 / T7 흡연 / T8 군중 혼잡 / T9 엘리베이터 내 쓰러짐 / T10 에스컬레이터 내 쓰러짐 / T11 월담 / T12 따라 들어가기 |

### 판정 단위 — 두 지표를 모두 산출한다

- **클립 단위 = 시험규격의 합격 판정.** 영상 1건이 표본 1개. 100건에서 TP/FP/FN을 집계한다.
- **프레임 단위 = 참고 지표.** 클립 판정만 보면 "영상 어딘가에서 한 번 맞혔다"와 "이벤트 구간을
  정확히 짚었다"가 구분되지 않는다. 시간축 정확도를 같이 남기기 위해 병행 산출한다.

클립 판정 규칙: 프레임 점수가 임계값 이상인 구간이 **연속 K 프레임 이상**이면 "발생"으로 본다.
단발 스파이크로 인한 오검출을 막기 위한 것이며, K·임계값은 설정 파일에 고정되고 시험 중 바꾸지 않는다.

## 2. 실행

```bash
set -a; . ./.env; set +a          # HF_TOKEN
PY=~/miniconda3/envs/pe_npu_host/bin/python

$PY -u -m wave_npu.tta_cert \
    --spec   wave_npu/specs/tta_4cat.json \
    --config wave_npu/specs/decision_4cat.json \
    --mxq    <PE-Core MXQ 경로> \
    --yolo-mxq <YOLO11 MXQ 경로> \
    --device-ids 0 \
    --out    wave_npu/artifacts/tta_run
```

- `-u`(버퍼링 해제)를 붙여야 진행률이 실시간으로 보인다.
- `--device-ids 0` : 시험 규격이 **NPU 1기** 기준이므로 시험 당일은 1기만 지정한다.
  (개발 중 여러 장을 쓰려면 `--device-ids 1,3,4,5` 처럼 나열)
- `--limit N` : 개발용. 폴더별 앞 N건만 처리.

### 화면에 표시되는 것

1. **진행 순서**를 먼저 띄운다 — 시험원이 지금 몇 번째 단계인지 따라올 수 있다.
2. **① 환경·모델 식별** — 장비/OS/커널, NPU 드라이버·런타임·펌웨어, 인식 장치 수,
   python·torch·torchvision, 그리고 **모델 md5 체크섬**(컴파일 로그 해시와 대조).
3. **③ 일괄 추론** — tqdm 진행바로 `건수 / 경과 / 남은시간 / 누적 프레임 / frame·s⁻¹`.
4. **② 데이터셋 식별** — 항목별 건수·양성·음성·총 프레임·해상도 구성.
   건수 100 미만이거나 음성 0건이면 경고를 띄운다.
5. **항목별 ③~⑥** — 판정 설정을 먼저 찍고, **오검출(FP)·미검출(FN) 건은 파일명·최대점수·
   최장연속프레임과 함께 한 줄씩** 출력한다(시험원이 그 자리에서 영상을 열어 확인 가능).
   이어서 집계 → P/R/F1 산식 전개 → 90점 판정.
6. **⑦ 최종 요약표** — 항목별 한 줄(클립 TP/FP/FN·P·R·F1·판정 + 프레임 F1 참고) 및 제출 자료 경로.

### 산출 파일

| 파일 | 용도 |
|---|---|
| `집계표.csv` | 항목별 TP·FP·FN·P·R·F1·판정 (클립 + 프레임) — 성적서 본문 근거 |
| `시험결과.json` | 환경·모델 md5·판정 설정·전체 결과 — 재현성 증빙 |
| `T{n}_{cat}_건별결과.csv` | **건별 원시 로그** — 파일명·해상도·프레임수·정답·판정·결과(TP/FP/FN/TN)·최대점수·최장연속·프레임별 집계 |

## 4. 성능

디코딩은 **동시 N건으로 제한한 선행 스레드**(`--decode-workers`, 기본 4)로 NPU 대기 뒤에 숨긴다.
원본 해상도 프레임을 메모리에 들고 있어(1080p 15초 ≈ 1.8 GB) 무제한 선행은 메모리가 먼저 터진다 —
초기 구현에서 실제로 RSS 32 GB까지 올라가 이 제한을 넣었다.

실측(4카드, 720p/828p 15초 영상 200건 = 72,200프레임): **47.3 frame/s / 25.4분**.

시험은 **NPU 1기** 기준이고 데이터는 12항목 × 100건 ≈ 1,200건(약 433,000프레임)이다.
카드 수와 건수를 단순 환산하면 수 시간 규모이므로, **시험 일정에 맞는지 반드시 사전 리허설로
실측**해야 한다(전처리가 CPU 바운드라 카드 수에 선형 비례하지 않는다).

## 5. 시험 전 확인 사항

- [ ] **항목당 100건** 확보 (미달 시 실제 건수를 성적서에 명시 — 합의서 예외사항)
- [ ] **12종 전체** 스펙·판정 설정 등록 (현재 4종: T1~T4)
- [ ] 정답 라벨링 시트 확정 — 파일명 목록과 "발생 여부"
- [ ] SW 버전 정합: 합의서 기재는 **드라이버 1.13 / 런타임 0.30.0 / 펌웨어 1.2.4**.
      시험 장비 상태와 일치하는지 확인하고, 시험 중 변경하지 않는다.
- [ ] 양자화 표기 정합: 합의서는 **Mixed-Precision(INT4/INT8/INT16)**.
      현 배포본은 W8A16(INT8/INT16)이라 INT4가 없다 — 모델을 바꾸거나 문구를 정정해야 한다.
- [ ] 모델 md5 = 컴파일 로그의 해시값 일치 확인 (스크립트가 md5를 찍어 준다)
